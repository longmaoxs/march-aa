# 从一张照片到 job.json（结构剖析的第一步）

用户只给一张照片时，不要直接猜参数。流程是：**先量、再认、后确认、最后出图**。

```
analyze_photo.py  →  形制草案（带 evidence/confidence）  →  人/agent 确认  →  structure_plate.py
```

## ① 量（脚本做）

```bash
PY=/Users/louis/workspace/3D/.tools/pocket-city-venv/bin/python
$PY scripts/analyze_photo.py --photo 照片.jpg --out draft.json
```

输出：主体外框（归一化）、长宽比、候选檐口线（数量 + 归一化 y）、左右对称度、明暗（天空/地面）。
这些只是**测量值**，不是结论——尤其「候选檐口线」里会混进瓦垄和台基线，必须人眼确认。

## ② 认（看照片，逐项填）

| 看什么 | 怎么判 | 写进哪 |
|---|---|---|
| 屋顶形式 | 四条戗脊汇于一点 = 攒尖；一条正脊两端各带一坡 + 山面三角 = 歇山；只有一条正脊两坡到底 = 硬山/悬山；无正脊、圆弧相交 = 卷棚 | `family` + `style` |
| 檐数 | 数「并排、等距、贯通的水平檐口线」，一道=单檐，两道=重檐 | `eaves` |
| 平面 | 正面看四角 = 方/长方；看得到三条以上斜边 = 六角/八角 | `plan` / `bays` |
| 间数 | 数正面柱间（明间 + 次间 + 梢间） | `bays` |
| 斗拱 | 檐下有一层层外挑的小方木 = 有；柱头直接顶檩 = 无 | `brackets` |
| 平坐 | 两层之间有一圈挑出的楼板 + 栏杆 | `floors` |
| 台基 | 数踏跺级数 / 有无须弥座 | 说明文字 |

## ③ 写 evidence 与 confidence

每一项都要能说出**凭什么**：

```json
"evidence": [
  {"item": "family", "value": "ting", "why": "四条戗脊在宝顶处交汇，屋面为四坡攒尖", "confidence": 0.9},
  {"item": "eaves", "value": 2, "why": "照片上有上下两道并排等距的檐口线", "confidence": 0.85},
  {"item": "bays", "value": "unknown", "why": "只拍到正面一角，数不出间数", "confidence": 0}
]
```

规矩：
- **看不清就写 unknown**，不要用「大概是」填空；
- 单张照片只能给一个视角时，平面形状与间数允许 `unknown`，出图用常规值占位，并在说明文字里写明「按常规做法占位」；
- 尺寸全部先按常识占位（面阔 3.6–4.2m、层高 2.2–2.6m、出檐 0.8–1.0m），再按照片里的比例微调。

## ④ 确认（必须的一步）

把「形制判断 + 每条的凭据 + 不确定项」列给用户，让他确认或改。**不要跳过**——
猜错一个 `bays`，整张图的柱网就全错，而图是要拿去讲构造的。

## ⑤ 出图

```bash
$PY scripts/structure_plate.py --json draft.json --out out/x.png
```

出图后回到照片对一遍：檐口层数、开间数、屋顶形式、台基高度。对不上就回去改 `params`。

## 常见错判

- **把重檐看成单檐 + 一圈装饰**：看檐口线是不是「两道等距、各自有起翘」。
- **把歇山看成庑殿**：歇山的两端山面上半是竖直的三角（山花），庑殿没有。
- **把抱厦当主体**：主体取「最高、最完整的那一组」，抱厦只进说明文字。
- **把近处的树/电杆算进主体**：主体框以外的东西一律不影响形制判断。

## 拍照要求（直接决定量比值的可信度）

正立面照片能标定的量有限，且对拍摄方式极其敏感。按下面的要求拍，误差能压到 5% 以内：

1. **正对立面**，相机高度约在建筑半高处（不要在街面上仰拍）；
2. **地平线水平**：取景框里让台基/地面线尽量水平，肉眼就能看出歪就别拍；
3. **中长焦**（等效 50–85mm），离得远一点；广角会把两端拉斜；
4. **建筑占满画面 60% 以上**，别让树和天空占主导——检测窗口会被带偏。

做不到的话，先跑一次矫正：

```bash
# 自动拉平（默认，安全）：取台基与檐口两条线的拟合角中位数，旋转图片
$PY scripts/analyze_photo.py --photo hall.jpg --rectify roll --mark /tmp/bands.png

# 四点透视（更准，需人手给一个"真实矩形"的四个角，归一化坐标 TL,TR,BR,BL）
$PY scripts/analyze_photo.py --photo hall.jpg \
    --rectify quad --quad 0.115,0.542,0.885,0.542,0.885,0.703,0.115,0.703 \
    --lines 0.703,0.542,0.492,0.416
```

报告里的 `measure.rectified` 会记下用了哪种矫正、检测到的角度、以及 `--quad` 的四个点，
便于回溯"这张图是矫正过的"。

### 误差上限（重要）

单条水平线的读数不确定度约 **±10 px**（占 853 px 高的 1.2%）。换到构件上：

| 量 | 相对误差 | 说明 |
|---|---|---|
| 台基高 / 柱高 | **±5%** | 线长、对比强，稳 |
| 柱高 / 总高 | ±2% | 最稳的一个量 |
| 斗拱层高 / 柱高 | **±20%** | 斗拱带只有 ~43 px，±10 px 就是 ±23% |
| 正脊长 / 面阔 | ±15% 且**系统性偏** | 脊在立面之后，投影高度受进深影响，不属于立面平面 |
| 举高（屋面坡度） | 只能估 | 正立面没有坡度信息 |

结论：**台基与柱高可以量，斗拱只能给区间，正脊与举高必须标"估"。**
报告里给数时请带区间（如「斗拱 0.27–0.31×柱高」），不要给一个看起来精确的单值。
