# 编号标注（callout）规范 — 坐标怎么定、号怎么排、怎么验收

> 这一篇是被用户连着否掉四版之后写下来的。**照着做，就不会再出现「编号都不对」**。

## 一、三条铁律

1. **编号顺序 = 构件清单顺序**，绝不能被任何版面排序（按 y 排序、避让重排）影响。
2. **标注坐标必须由「实际绘制出来的像素」反算**，不许从缩放过的预览图上肉眼估。
3. **徽标不许离开构件**。只有「在画面上完全不露头」的构件（如被屋面压住的内槽金柱、被柱身挡住的柱础）才允许一根 **≤ 0.05 画布高**的短引线。

## 二、三次翻车的真实原因（记住症状，别再猜）

| 症状 | 真因 |
|---|---|
| 「02/03/04…都不对」，但位置看着都挺像 | `cals.sort(key=lambda c: -_pp(c)[1])` 之后才 `enumerate` → **编号按屏幕高度重排**，图例却按构件清单生成，号与构件整体错位 |
| 自检 10/10 通过，用户仍说全错 | 自检判据是「锚点像素所属的 part == 期望 part」，而自检用的 id 图与 `draw_model` 的遮挡顺序不一致（半透明屋面视觉上在前、id 图里在后） |
| 每次改都差 2–5% 画布宽（50–120 px） | 在 1134 px 宽的预览图上肉眼读分数坐标。预览被缩过、还有边距，读出来的数必然错 |

## 三、正确做法

### 3.1 编号：先记原序，再排序

```python
num_of = {id(c): i for i, c in enumerate(cals)}     # ① 先记住构件清单原序
cals.sort(key=lambda c: -_pp(c)[1])                 # ② 排序只为避让，不再赋号
placed = [_pp(c) for c in cals]
...
cv.text(sx, sy + 2, '%02d' % (num_of[id(c)] + 1), f_num, ACCENT_DEEP, anchor='mm')
```

图例（左下角 01…10）必须用**同一个** `cals` 原序生成，二者天然对齐。

### 3.2 坐标：录绘制、栅格化、反查 part

不讲道理的版本（可直接抄）：

1. **录**：渲染前 monkeypatch `Canvas.poly`，把每次 `fill is not None` 的顶点按调用顺序存下来。
   这就是"真实绘制顺序"，比任何排序推导都可靠。
2. **配**：对 `model['faces']` 每张面用 `SP._fs(f)` 取 quad、`ax.pt()` 投影到逻辑坐标，
   把顶点四舍五入成元组做字典键 → `{顶点签名: meta['part']}`（正反序各存一份）。
3. **栅**：新建 `Image.new('I', (W*S, H*S))`，按录制顺序 `polygon(pts, fill=序号)`，
   同时记 `{序号: part}`。像素值即"最后画上去的那张面"，与成图逐像素一致。
4. **取**：按 part 收集可见像素；常规构件取"离该 part 微质心最近"的点。
5. **出**：除以 `W、H` 得分数坐标，写进样本 JSON。

```python
im = Image.new('I', (W*S, H*S), 0); d = ImageDraw.Draw(im)
for n, pts in enumerate(rec, 1):
    part = sig.get(tuple((round(x,1), round(y,1)) for x, y in pts))
    if part:
        pmap[n] = part
        d.polygon([(x*S, y*S) for x, y in pts], fill=n)
```

实测可见像素数（hall_tang）：屋面 136k、墙体 53k、台基 41k、额枋 16k、门窗 5.5k、
梁架 4.9k、斗拱 4.7k、柱身 4.5k、正脊 2.2k、**柱础 168**（柱脚鼓形被柱身挡掉大半，但仍真实可见）。

### 3.3 取点规则

| 构件类型 | 取法 |
|---|---|
| 常规（台基、墙、门窗、额枋、斗拱、梁架、正脊、屋面） | 该 part 可见像素的微质心最近点 |
| 细长或被压（柱础） | 同上；像素少也可用，别再外移 |
| 屋面角部构件（翼角） | 取屋面可见像素里 `max(x + y)` 的点（= 最外侧檐角） |
| 画面上完全不可见（内槽金柱） | 徽标给"构件屏幕邻域"的坐标，再用 `_lead_to` 拉一根短引线 |

### 3.4 写回样本 / 落图

```json
"callout_xy": {
  "台基踏跺": [0.456, 0.735],
  "金柱":     [0.525, 0.618, 0.525, 0.653]
}
```

- 两个数：`[x, y]`，徽标就压在构件上，**不画引线**。
- 四个数：`[x, y, ax, ay]`，徽标在 `(x,y)`，虚线指到 `(ax,ay)`（仅限必须的情况）。
- 坐标是**分数**（0–1），与画布尺寸、缩放无关；换版式不用改数。

渲染侧在 `render()` 里 `model = _apply_xy(job, model)` 应用，`_pp(c)` 的优先级：
`c['xy']` → `c['_pxy']` → `ax.pt(c['at'])`。

### 3.5 验收（缺一不可）

1. 反算脚本逐条打印 `label / part / 可见像素数`，`part` 必须等于 `_part_of(label)`；
2. **人眼只确认一件事**：徽标压在该构件轮廓内（不再量坐标）；
3. `python scripts/check.py` 全绿。

## 四、反例清单（写代码时看到就停）

- ❌ `_snap_visible`（吸"最近任意面"）——编号会集体跑到屋面上。
- ❌ 直接把"该 part 全部可见像素的质心"当锚点——大面积构件（墙、屋面）的质心在别处。
- ❌ 用 `-hd` 当正面。本轴测 `Axo(c=0.866, s=0.5, zk=0.95)` 里 **`+y` 才是正面（有门一侧）**。
- ❌ 在缩放过的 PNG 预览上读坐标。
- ❌ 让引线去追一个本来就标对的位置——引线是补救，不是常态。

## 五、一句话总结

> 号按清单排、点按像素算、徽标压构件、引线只兜底。
